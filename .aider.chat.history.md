#### How does the /prod vs /test URL prefix determine which database is queried?  

The `/prod` vs `/test` URL prefix determines which database is queried through Flask's dynamic routing and how that value is used to establish the database connection.

Here's a step-by-step breakdown of how it works in `server1.py`:

1.  **Dynamic URL Routes**: All the API endpoints are defined with a variable `<db>` in their URL path. For example:
    ```python
    @app.route("/<db>/api/companies/<ticker>", methods=["POST"])
    ```

2.  **Flask Captures the Value**: When a request is made, Flask captures the value from that part of the URL.
    *   For a request to `/prod/api/companies/AAPL`, Flask sets `db = "prod"`.
    *   For a request to `/test/api/companies/AAPL`, Flask sets `db = "test"`.

3.  **Value Passed to View Function**: Flask passes this captured value as an argument to the function that handles the endpoint. Notice the `db` parameter in the function signature:
    ```python
    def add_company(db, ticker):
        # ...
        conn = get_db(db)
        # ...
    ```

4.  **Database Connection**: The `db` variable, containing either `"prod"` or `"test"`, is then passed to the `get_db()` function. This function uses the value as the `database` name when connecting to MySQL:
    ```python
    def get_db(db):
        return mysql.connector.connect(
            host="mysql",
            user="root",
            password="acid",
            database=db,  # This will be "prod" or "test"
        )
    ```

So, the first segment of the URL path directly and dynamically determines which database is used for all subsequent operations within that request.

    query = "SELECT date, high, name FROM stocks WHERE ticker = %s"
    rows = session.execute(query, (ticker,))

    monthly_data = {}

        if month_str not in monthly_data:
            monthly_data[month_str] = {"sum": 0, "count": 0}
